# Herndon OS — Required Actions / Action Items Redesign Spec

**Date:** June 2026  
**Status:** APPROVED — ready to build  
**Reviewed by:** Claude + ChatGPT  
**Scope:** Weekly Model view, History tab, custom task data model

---

## Problem Statement

The current "Required Actions This Week" section mixes two fundamentally different things: money movements that need to happen (transfer $375 to Tax Reserve) and to-do tasks that don't move money (review Jabian reimbursements, look into AMEX due date). This causes:

1. The "Transfers This Week" panel labels non-transfer custom tasks as "Pending Transfers" — wrong.
2. "Recommended Review This Week" (auto-generated credit card reminders) has no completion tracking — not in History, can't be checked off.
3. No distinction between system-generated reminders and user-created tasks — they're indistinguishable after the fact.

---

## Section Redesign

### Renamed sections

| Old name | New name | Content |
|---|---|---|
| Transfers This Week (panel) | **Transfers This Week** | Model transfers with completedAmount normalization. Completed custom transfers appear with ✅. No uncompleted custom tasks. |
| Required Actions This Week | **Transfers to Execute** | Model-generated transfers + transfer-type custom tasks only |
| Recommended Review This Week | **Action Items** | Auto-generated credit card reminders + action-type custom tasks |

Both "Transfers to Execute" and "Action Items" have completion checkboxes and are tracked in History.

## Data Model

### Final custom task shape

```js
{
  id,                          // existing — stable UUID
  label,                       // existing — display text
  completed,                   // existing — boolean
  type: 'transfer' | 'action', // NEW — routes to section and panel
  source: 'user' | 'auto_reminder', // NEW — provenance
  reminderKey: null | string,  // NEW — stable identity for auto-reminders
  lockedLabel: false,          // NEW — true for auto-reminders (label not user-editable)
  dismissed: false,            // NEW — suppresses auto-reminder regeneration
  version: 1                   // NEW — schema version for future migrations
}
```

### Type semantics

**`type: 'transfer'`** — a movement of money between accounts.
- Shows in Transfers to Execute
- When `completed: true`, also appears in Transfers This Week panel with ✅
- When `completed: false`, does NOT appear in top panel

**`type: 'action'`** — a task, reminder, or investigation that does not move money.
- Shows in Action Items only
- Never appears in Transfers This Week panel

### Source semantics

**`source: 'user'`** — created by Adam via "+ Add Transfer" or "+ Add Task" button.

**`source: 'auto_reminder'`** — generated by the model (credit card statement closes, due-date warnings). Has a stable `reminderKey`. Label is locked (`lockedLabel: true`).

## Auto-Reminder System

### Stable reminderKey format

```
{year}_w{weekNum}__{reminderType}
```

Examples:
```
2026_w25__amex_platinum_close
2026_w25__disney_visa_close
2026_w25__review_cashflow
2026_w28__alaska_due_date_warning
```

### Idempotent auto-generation

When rendering a week, before inserting a model-generated reminder as a custom task:

1. Check `customTaskData[weekNum]` for an existing entry with the same `reminderKey`
2. If found: do not insert — existing entry (completed or dismissed) wins
3. If not found: insert with `source: 'auto_reminder'`, `completed: false`, `dismissed: false`

### Suppression logic

Do not regenerate an auto-reminder for the current `reminderKey` if:
- An entry with that key exists and `completed: true`, OR
- An entry with that key exists and `dismissed: true`

### Dismissal

Add an ✕ dismiss button on Action Items entries where `source: 'auto_reminder'`. Sets `dismissed: true` and persists. Does not delete the record — keeps it as a suppression sentinel.

User-created tasks (`source: 'user'`) use the existing ✕ delete button (which removes the record entirely).

## Metadata Preservation Audit

**Risk:** Any write path that reconstructs a task object as `{ id, label, completed }` will silently drop `source`, `reminderKey`, `lockedLabel`, `dismissed`, `version`, and `type`.

**Required fix on every write path:**

```js
// WRONG — drops metadata
taskData[key] = { completed: true, completedAt: now, ... }

// RIGHT — spreads existing, overrides only what changed
taskData[key] = Object.assign({}, taskData[key] || {}, { completed: true, completedAt: now, ... })
```

**Paths to audit and fix:**

| Path | Location | Action |
|---|---|---|
| `toggleTask()` | ~line 1701 | Spread existing task, only override completion fields |
| `saveTask()` / add custom task | ~line 1219 | Write full shape including all new fields |
| `editTask()` / label update | ~line 1226 | Spread existing, only override label |
| Migration at `loadAll()` | ~line 3809 | Spread after hydration, add missing fields with defaults |
| `renderHistory()` | ~line 3531 | Read-only — no write concern |
| Supabase save (`goals` table `custom_tasks`) | serialize/stringify path | Ensure full object is serialized, not subset |
| Auto-reminder insertion | New code | Write full shape with all fields populated |

## Migration Plan

### One-time migration for existing custom tasks

Run at `loadAll()` after hydrating `customTaskData` from Supabase:

```js
Object.keys(customTaskData).forEach(function(wk) {
  customTaskData[wk] = customTaskData[wk].map(function(ct) {
    if (ct.version >= 1) return ct; // already migrated
    var isTransfer = /\$/.test(ct.label) && /(Transfer|→)/.test(ct.label);
    return Object.assign({
      type: isTransfer ? 'transfer' : 'action',
      source: 'user',
      reminderKey: null,
      lockedLabel: false,
      dismissed: false,
      version: 1
    }, ct);
  });
});
```

Persist migrated data back to Supabase on next save.

## History Tab Changes

### Completion counts

History task counts include all four categories:

1. Completed model transfer actions (unchanged)
2. Completed transfer-type custom tasks (unchanged behavior)
3. Completed action-type custom tasks (NEW — currently not counted)
4. Completed auto-generated reminders (NEW — currently not counted)

### Badge format

**Card-level badge (scannable):** `5/7 done`

**Expanded week detail (inside the history card):**
```
Transfers:    3/4
Action Items: 2/3
```

### Open/Partial/Done logic

- **Done** — all tasks in both sections complete (or dismissed)
- **Partial** — at least one complete across either section
- **None** — nothing complete

## Identified Risks

| Risk | Mitigation |
|---|---|
| Metadata dropped on save | Audit all write paths; use Object.assign spread pattern |
| Migration heuristic misclassifies a task | Type-edit affordance allows manual correction |
| Auto-reminder recreated after dismissal | Idempotent check on reminderKey before insert |
| reminderKey collision across years | Include year in key format: `2026_w25__...` |
| lockedLabel reminder has wrong label after model change | Auto-reminders regenerate label on insert only; existing entry keeps its label unless deleted |
